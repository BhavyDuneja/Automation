## 1. Executive summary

anantasutra.com has a sound technical base: server-rendered pages, HTTPS with HSTS, real 404s, no broken internal links in the 40 crawled pages, Article and BreadcrumbList schema on every sampled post, an `llms.txt`, and no AI crawler blocked. What holds it back is a short list of template mistakes that tell Google to ignore the money pages. In 28 days Search Console shows 189 page impressions and 1 click, none for hiring or dedicated-expert terms, and not one impression for any `/services/*` page. The main cause is technical: 14 of 16 service pages, including the flagship `/services/dedicated-experts`, declare `/services` as their canonical and share its title and description; `/portfolio` and `/testimonials` canonicalize to the homepage; every canonical and sitemap URL uses the apex host, which 307-redirects to www; and the sitemap leaves out at least 17 live posts. **Overall: needs work, with critical canonical errors on a sound base.** About a day of developer time on templates should fix most of it; the larger gain then comes from building the hire-intent pages the site does not have.

- **Biggest strength:** a crawlable, mostly static site with deep blog content (1,370 to 1,724 words per sampled post), working schema on posts, and open access for search and AI bots.
- **Top 3 priorities:**
  1. Fix canonicals and per-route metadata (14 service pages, `/portfolio`, `/testimonials`), choose one host with a permanent redirect, and rebuild the sitemap. About 1 to 1.5 developer days (estimate).
  2. Build the missing hire-intent pages: `/hire/<role>` for the domains the site sells (start with 6) and `/pricing`; finish or `noindex` the 5 "Coming soon" pages. About 2 to 3 weeks (estimate).
  3. Make the blog crawlable, fast and connected to the services: server-render `/blog`, serve posts statically (ISR), repair the empty social-preview image, add a service call to action to each post. About 2 to 3 developer days plus ongoing content (estimate).

## 11. Paste-ready fixes

### 11.1 One host, one redirect

**Recommendation: use the apex, `https://anantasutra.com`.** Canonical tags, `og:url`, the sitemap, `llms.txt`, JSON-LD, GSC history and the brand materials already use it. The only thing that disagrees is Vercel's domain redirect (apex to www, status 307), so flipping that one setting aligns everything without code changes. Vercel's docs (read 2026-10-09) recommend `www` as the primary and say redirecting `www` to the apex "also works but provides Vercel less control over incoming traffic"; that is an infrastructure preference, not an SEO one. If you would rather follow Vercel's default, choose `www` and replace the host in `SITE_URL` (section 11.5), the sitemap, `llms.txt` and JSON-LD.

1. Vercel, Project Settings, Domains: make `anantasutra.com` a production domain with no redirect.
2. Edit `www.anantasutra.com` and set "Redirect to" `anantasutra.com`. If the dialog lets you choose the status code, choose permanent (308). If it only gives 307, remove the domain-level redirect and use the rule below instead (a domain-level redirect runs before the app, so these are alternatives):

```js
// next.config.js
module.exports = {
  async redirects() {
    return [
      {
        source: '/:path*',
        has: [{ type: 'host', value: 'www.anantasutra.com' }],
        destination: 'https://anantasutra.com/:path*',
        permanent: true, // sends 308
      },
    ]
  },
}
```

3. Define the host once (`SITE_URL`, section 11.5) and use it for `metadataBase`, the sitemap, `robots.ts`, JSON-LD and the links in `llms.txt`.
4. Expect Search Console to report the www URLs as "Page with redirect" or "Alternate page with proper canonical tag" for some weeks. That is normal.

### 11.3 Sitemap

The live sitemap omits at least 17 posts that return 200 (confirmed one by one), so it is not generated from the same source as the blog. Make `app/sitemap.ts` read the same function the blog index uses.

```ts
// app/sitemap.ts
import type { MetadataRoute } from 'next'
import { SITE_URL } from '@/lib/site'
import { getAllPublishedPosts } from '@/lib/posts' // the SAME query the blog index uses

export const revalidate = 3600

const PAGES = [
  '', '/about', '/services', '/services/dedicated-experts', '/services/ai-automation', '/services/voice-agents',
  '/services/recruiter-ai', '/services/gmail-automation', '/services/social-automation', '/services/social-media',
  '/services/video-generators', '/services/content-shooting', '/services/ai-marketing', '/services/marketing',
  '/portfolio', '/testimonials', '/apps', '/contact', '/blog', '/co-founder',
  // add '/pricing', '/hire' and each '/hire/<role>' as they ship.
  // leave out /services/ecommerce, /real-estate, /immigration, /business, /academic until they are real pages.
]

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const posts = await getAllPublishedPosts()
  return [
    ...PAGES.map((path) => ({ url: `${SITE_URL}${path}` })), // no lastModified unless you track real edit dates
    ...posts.map((post) => ({ url: `${SITE_URL}/blog/${post.slug}`, lastModified: post.updatedAt })),
  ]
}
```

**3. One helper for every page.** It rebuilds the whole `openGraph` object each time, because a child replaces the parent's.

```ts
// lib/seo.ts
import type { Metadata } from 'next'
import { SITE_NAME, DEFAULT_OG_IMAGE } from '@/lib/site'

type PageSeo = {
  path: string          // '/services/voice-agents': no host, no trailing slash
  title: string         // the full <title> as rendered (60 characters or fewer)
  description: string   // 155 characters or fewer
  image?: string
  type?: 'website' | 'article'
  noindex?: boolean
  publishedTime?: string
  modifiedTime?: string
}

export function pageMetadata(p: PageSeo): Metadata {
  const image = p.image ?? DEFAULT_OG_IMAGE
  const og = {
    url: p.path,
    title: p.title,
    description: p.description,
    siteName: SITE_NAME,
    locale: 'en_IN',
    images: [image],
  }
  const meta: Metadata = {
    title: { absolute: p.title }, // ignores the layout template
    description: p.description,
    alternates: { canonical: p.path }, // self-referencing, resolved against metadataBase
    openGraph:
      p.type === 'article'
        ? { ...og, type: 'article', publishedTime: p.publishedTime, modifiedTime: p.modifiedTime }
        : { ...og, type: 'website' },
    twitter: { card: 'summary_large_image', title: p.title, description: p.description, images: [image] },
  }
  if (p.noindex) meta.robots = { index: false, follow: true }
  return meta
}
```

## 12. Data that was missing, and caveats
